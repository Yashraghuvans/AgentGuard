Architecture

Every agent call passes through five gates

There is no bypass. A failure at any gate immediately returns a BLOCK decision, publishes an audit event, and never reaches your business logic.

Capabilities

What gets enforced at every call

All five gates run sequentially. Policies control which checks apply and at what thresholds.

Schema Validation
Validates payload keys, field types, required fields, enum values, and numeric ranges against a declared JSON schema contract. Unknown keys are rejected — fail closed.
CRUD / FLS Enforcement
Evaluates the requesting user's object and field permissions using WITH USER_MODE. Supports READ, CREATE, MODIFY, and REMOVE operations. Restricts by profile or permission set.
Rate Limiting
Sliding-window per-user, per-action invocation counter backed by Platform Cache. Configurable call budget and window length per policy. Fails open with a flagged audit event on cache unavailability — never silently.
Transactional Rollback
Opens a Salesforce Savepoint before business logic executes. Any unhandled exception automatically rolls back all DML within the call. Enforces a hard ceiling on records per call to prevent bulk mutation attacks.
Real-Time Audit
Publishes one AgentGuard_Audit__e Platform Event per decision — including actor ID, hashed payload, gate name, decision, reason, and latency. Events publish outside the rollback boundary and survive transaction failures.
Declarative Policies
All enforcement rules live in Guard_Policy__mdt Custom Metadata Type records. Change thresholds, toggle gates, and update schemas without deploying Apex.
Installation

Set up in four steps

Requires Salesforce DX CLI and a Dev Hub org. Works with Developer Edition, scratch orgs, and production sandboxes.

1
Install the Salesforce CLI
If you don't have it already:
npm install -g @salesforce/cli
sf --version
2
Clone the repository
git clone https://github.com/yashraghuvanshi/agentguard-sf.git
cd agentguard-sf
3
Create a scratch org and deploy
# Authenticate to your Dev Hub
sf org login web --set-default-dev-hub --alias devhub

# Create a scratch org (or target an existing sandbox)
sf org create scratch \
  --definition-file config/project-scratch-def.json \
  --alias agentguard-dev \
  --duration-days 30 \
  --set-default

# Deploy all metadata
sf project deploy start --target-org agentguard-dev
4
Create the Platform Cache partition
In your org, go to Setup > Platform Cache, create a new partition named AgentGuard with at least 1 MB of org cache allocated. This partition is required for rate limiting to function.
Then verify the installation by running the test suite:
sf apex run test \
  --target-org agentguard-dev \
  --code-coverage \
  --result-format human \
  --wait 30
Expected: 75 tests, 100% passing, org-wide coverage above 75%.
Integration Guide

Add AgentGuard to an existing action

No changes to your business logic are required. Add one check before your existing code executes.

Before — unprotected
@InvocableMethod(label='Update Territory')
public static List<Result> execute(
    List<Request> requests
) {
    // AI input goes directly into DML
    return TerritoryService.reassign(requests);
}
After — protected by AgentGuard
@InvocableMethod(label='Update Territory')
public static List<Result> execute(
    List<Request> requests
) {
    GuardResult check = AgentGuard.wrap(
        'UpdateAccountTerritory', // policy name
        JSON.serialize(requests)  // payload
    );

    if (!check.isAllowed) {
        throw new AgentGuard.BlockedException(
            check.reason,
            check.decision,
            check.gateName
        );
    }

    // Existing logic — unchanged
    return TerritoryService.reassign(requests);
}
Automatic rollback pattern
Use wrapAndExecute when your action performs DML. If business logic throws, the Savepoint is automatically rolled back and a ROLLBACK audit event is published. 
private class TerritoryCallback implements RollbackGuard.GuardResultCallback {
    private List<Request> requests;
    public TerritoryCallback(List<Request> reqs) { this.requests = reqs; }

    public GuardResult execute(GuardResult allow) {
        // DML here is automatically rolled back on exception
        return TerritoryService.reassign(this.requests);
    }
}

// In your @InvocableMethod:
GuardResult result = AgentGuard.wrapAndExecute(
    'UpdateAccountTerritory',
    JSON.serialize(requests),
    new TerritoryCallback(requests)
);
Policy Configuration

Guard_Policy__mdt field reference

Create one Custom Metadata record per action. All fields default to their most restrictive value. Nothing is permitted unless explicitly configured.

Field Type Default Description
DeveloperName Text — Must match the first argument passed to AgentGuard.wrap()
IsActive__c Checkbox false Master kill-switch. When false, all calls are blocked immediately at AccessGate
TargetSObjectType__c Text empty API name of the object the action reads or writes. Required for AccessGate to run
Operation__c Text READ One of: READ, CREATE, MODIFY, REMOVE. Determines which CRUD/FLS checks apply
SchemaContract__c Long Text empty JSON schema document. Blank blocks all calls at SchemaValidator
MaxRecordsPerCall__c Number 0 Hard ceiling on DML rows per call. Zero blocks all calls at RollbackGuard
RateLimitPerMinute__c Number 0 Max calls per user per window. Zero blocks all calls at RateLimiter
RateLimitWindowSeconds__c Number 60 Sliding window length in seconds. Clamped to 10–3600
AllowedProfiles__c Long Text empty Semicolon-delimited profile names. Empty means no profile restriction
AllowedPermissionSets__c Long Text empty Semicolon-delimited permission set names. Empty means no permission set restriction
Example schema contract
{
  "properties": {
    "AccountId":   { "type": "string" },
    "Territory__c": { "type": "string" },
    "RecordCount": { "type": "integer", "minimum": 1, "maximum": 100 }
  },
  "required": ["AccountId"]
}
Supported types: string, integer, number, boolean, array, object. String fields support an "enum" constraint. Numeric fields support "minimum" and "maximum". Any field can be marked "nullable": true to allow explicit nulls.
Security

Threat coverage by STRIDE category

Threat Component Mechanism
Spoofing AccessGate Evaluates real running-user permissions — never a claimed or elevated context
Tampering SchemaValidator Rejects payloads with unknown fields, wrong types, or missing required fields
Repudiation AuditPublisher Publishes actor ID, payload hash, decision, and reason on every call — including blocked ones
Information disclosure AccessGate Blocks read paths for fields the requesting user cannot see
Denial of service RateLimiter Per-user, per-action sliding window throttle rejects excess calls before they reach business logic
Elevation of privilege RollbackGuard Savepoint boundary and record ceiling prevent partial bulk mutations from leaving inconsistent state
Full threat model: docs/threat-model.md. Known limitations and mitigations: docs/risk-register.md.
